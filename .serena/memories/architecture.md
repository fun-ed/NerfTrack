# Architecture invariants
- Discovery precedence: persisted selection → accessible `CODEX_HOME` (including an explicit empty future folder) → ordered platform candidates → explicit missing/unsupported status. Automatic candidates require safe traversal and a plausible readable `.jsonl`; a manually selected empty directory is retained as waiting for data.
- Desktop and CLI records share one discovery→collector→parser→storage→estimator pipeline. Collector must use `Path` APIs, canonical-directory tracking, reject recursive links, preserve byte/parser checkpoints, and tolerate partial final lines.
- SQLite database belongs in platform-native per-user app-data, never the repository/current working directory. It holds normalized events/checkpoints/settings/diagnostics and audit fields—not raw JSONL, prompts, or raw identifiers.
- Startup starts a named background worker after opening the window. An unchanged pricing/estimator/install marker preserves the graph and checkpoint-imports new records; a changed marker triggers transactional historical reparse/reprice/rebuild. Failures preserve the prior graph and commands must not block on background work.
- Pricing uses only models.dev's direct OpenAI model catalog (or retained/embedded fallback); manual local overrides win. The outbound request sends no usage/account/prompt content. Estimator never fabricates estimates for invalid, reset, zero/negative, unknown-price, or insufficient-confidence intervals.
- Fast mode requires explicit `thread_settings_applied` service-tier evidence scoped to the same rollout/session. `priority`/`fast` are Fast; `default` Standard; missing/unrecognized values stay Unknown with 1.0x. No heuristic may infer historical Fast mode.
